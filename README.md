# axum_dsl

A command line interface to compile a Ruby(ish) domain specific language into a working axum HTTP
service in Rust.

`axum_dsl` reads a `.axum.rb` file, parses it with Prism, and emits a Rust crate that uses the
[axum](https://crates.io/crates/axum) web framework. Build the crate with cargo to get a service that
answers HTTP.

`axum_dsl` also has an [`lsp` subcommand](docs/cli.md) (`axum_dsl lsp`): a language server on stdio that
compiles the buffer you are editing, so diagnostics, hover and completion come from the same compiler
`build` runs. `axum_dsl check FILE --format json --types` remains the batch path, printing the compiler's
errors (with suggestions) and the type it inferred for every parameter, local and expression. See
[Editor support](docs/editor-support.md).

Parts of code that need a Rust library come in through typed bindings (`use_bindings`).

The route bodies are ordinary-looking Ruby: strings, lists, integers, `if`, `case`, blocks, guard
clauses, helper functions.

Status: a working proof of concept, not a released tool. The emitted crate builds against axum 0.8
(verified with 0.8.9).

Ported from `rmcp_dsl`, which compiles the same Ruby subset to an MCP server on the `rmcp` SDK. Built
with Claude Sonnet 5.5 and Deepseek v4.1 Flash using the Claude Code and Opencode harnesses and the raj
editor.

## Requirements

- Ruby 4.0.7 (see `.tool-versions`) with the `prism` gem (`bundle install`)
- Rust (rustc and cargo) for building rust code output
- Optional: `sorbet` (`srb tc`) for the structure check of the DSL files

## Quick start

```ruby
# examples/add.axum.rb
# typed: true
server "calculator", version: "0.1.0"
set :port, 8080

params :CalcParams do
  field :a, :i32, in: :query
  field :b, :i32, in: :query
end

get "/add", params: :CalcParams, description: "Add two integers" do
  text((params[:a] + params[:b]).to_s)
end

params :UserId do
  field :id, :i64, in: :path
end

get "/users/:id", params: :UserId, description: "One user's id, as JSON" do
  json(params[:id])
end
```

```sh
ruby exe/axum_dsl check examples/add.axum.rb      # validate only; writes nothing
ruby exe/axum_dsl build examples/add.axum.rb      # write build/add and run cargo build
ruby exe/axum_dsl run examples/add.axum.rb        # build, then serve HTTP
ruby exe/axum_dsl dev examples/add.axum.rb        # build, serve, and rebuild and restart when an input changes
ruby exe/axum_dsl init my_service                 # scaffold my_service.axum.rb and bindings/
```

The `/add` and `/users/:id` routes compile to this Rust. It is an excerpt of `test/golden/add.main.rs`, the
crate's `main.rs` as `examples/add.axum.rb` builds it, which `make golden` checks against the compiler. The
example's third route (`/slow`, a `cmd_fn` subprocess) and its helper are left out:

```rust
// Generated by axum_dsl 0.1.0 from add.axum.rb. Do not edit.
#[derive(serde::Serialize, serde::Deserialize)]
struct CalcParams {
    a: i32,
    b: i32,
}

#[derive(serde::Serialize, serde::Deserialize)]
struct UserId {
    id: i64,
}

// overflow-checked integer arithmetic (only what this server uses): written by the compiler
fn arith_error(op: &str, a: impl std::fmt::Display, b: impl std::fmt::Display, b_is_zero: bool, ty: &str, min: i128, max: i128, at: &str) -> String {
    // ... the division-by-zero and overflow messages ...
}

fn ck_add_i32(a: i32, b: i32, at: &str) -> Result<i32, String> {
    a.checked_add(b).ok_or_else(|| {
        arith_error("+", a, b, b == 0, "i32", i32::MIN as i128, i32::MAX as i128, at)
    })
}

fn internal_error(message: &str) -> ::axum::response::Response {
    let mut response = ::axum::response::IntoResponse::into_response(message.to_string());
    *response.status_mut() = ::axum::http::StatusCode::INTERNAL_SERVER_ERROR;
    response
}

fn error_response(message: &str) -> ::axum::response::Response {
    internal_error(message)
}

#[allow(unused_variables)]
async fn route_1(axum::extract::Query(__query): axum::extract::Query<CalcParams>) -> ::axum::response::Response {
    let CalcParams { a, b } = __query;
    let response = match (|| -> Result<::axum::response::Response, String> {
        Ok(::axum::response::IntoResponse::into_response(ck_add_i32(a, b, "examples/add.axum.rb:11:9 in route `get /add`")?.to_string().to_string()))
    })() {
        Ok(response) => response,
        Err(message) => error_response(&message),
    };
    response
}

#[allow(unused_variables)]
async fn route_2(axum::extract::Path(__path): axum::extract::Path<UserId>) -> ::axum::response::Response {
    let UserId { id } = __path;
    let response = ::axum::response::IntoResponse::into_response(::axum::Json(id));
    response
}

// ... shutdown_signal(): resolves on ctrl-c or SIGTERM so the server drains ...

#[tokio::main]
async fn main() -> anyhow::Result<()> {
    let router = axum::Router::new()
        .route("/add", axum::routing::get(route_1))
        .route("/users/{id}", axum::routing::get(route_2))
        .route("/slow", axum::routing::get(route_3));
    let port = match std::env::var("PORT") {
        Ok(value) => match value.parse::<u16>() {
            Ok(port) => port,
            Err(_) => {
                eprintln!("PORT must be a port number from 0 to 65535, got {value:?}");
                std::process::exit(2);
            }
        },
        Err(_) => 8080,
    };
    let bind = std::env::var("BIND").unwrap_or_else(|_| "127.0.0.1".to_string());
    let listener = tokio::net::TcpListener::bind((bind.as_str(), port)).await?;
    axum::serve(listener, router.into_make_service_with_connect_info::<std::net::SocketAddr>())
        .with_graceful_shutdown(shutdown_signal())
        .await?;
    Ok(())
}
```

While the rust code is not terrible, I have a strong preference for the ruby code.

My hypothesis with this library is that having a middle layer between prompt and rust code output
can be beneficial.

## Install

As a gem: `gem build axum_dsl.gemspec`, then `gem install axum_dsl-0.1.0.gem`, then `axum_dsl --help`.
`make gem-test` builds the gem and installs it into a throwaway `GEM_HOME`. `axum_dsl skill`
writes an agent skill folder (`axum-dsl/`) into the current directory, for any agent that reads
`SKILL.md`.
