# How much is covered

_See also: [README](../README.md), [Views](views.md)._

`axum_dsl` was ported from `rmcp_dsl`, whose target is the server side of MCP. Ours is an axum HTTP
service, so this table is not "how much of axum" but **how much of the ported surface works, and what is
still unbuilt**. ✓ works, ◐ partly, ✗ not done. Every ✓ says what proves it — a test file, a golden, an
e2e script, a `bin/probe` row, the `emit.rb` line, or the refusal that enforces the rule — because a ✓
with no evidence is the one thing this table must not contain. Keep the ◐ and ✗ rows: the point of the
table is to state limits, not to look finished. This is the running list; the compiler's message is the
authority where the two disagree.

## The compiler and the emitted service

| ✓ | form bodies: `field ..., in: :form` reads an `application/x-www-form-urlencoded` body with axum's `Form` extractor (the emitted Cargo.toml gains axum's `form` feature only then — `Emit#axum_features`, pinned by `test/golden/validate.Cargo.toml` — and no new crate: axum's `query` feature already pulls serde_urlencoded); the generated `check()` runs on the parsed struct, and a body the extractor cannot parse is answered by axum itself with 422, where a value that parses but breaks a constraint is the 400 the check() gives (`examples/validate.axum.rb`'s three `in: :form` routes; `test/e2e_validate.sh` asserts the answers; `test/refusals/form_and_body.rb` refuses a group that mixes `:body` and `:form`; a field may carry a Rails wire name with `name: "message[body]"`, a serde rename that leaves `params[:body]`, `check()` and `errors` keyed by the DSL name, refused on a non-form field or a duplicate wire key (`examples/validate.axum.rb` `/messages`, `test/e2e_validate.sh`, `test/test_compiled_paths.rb`; `test/refusals/form_name_*.rb`)) |
| ✓ | `errors[:field]` in a route body: the generated `check()`'s message for that field (one per violated field, `""` when the request passed it or that field was fine), bound by the handler, which then keeps the 400 unless the body sets `status(...)` — a route that never names it is still answered 400 before its body runs. It carries only the `check()`'s violations: an extractor-level rejection (a missing field, a value that is not the field's type) is axum's own 422 and never reaches the body, the same split as the form row. `errors` with no `params:`, or with a group that declares no constraint, is refused (`examples/validate.axum.rb` and `examples/views.axum.rb`; `test/e2e_validate.sh` asserts the message reaches the body while the 400 stays, and the 202 when the body sets `status(:accepted)`; `test/refusals/errors_without_params.rb`, `errors_without_constraints.rb`) |
| ✓ | response helpers `text`, `html`, `json`, `redirect`, `halt` and `render`; `redirect` answers 302 by default and takes `status:` (301, 302, 303, 307, 308), while `text`/`html`/`json`/`render` take a literal `status:` and a string-literal `content_type:` that ride on the value so a `return` carries them; the `content_type` statement (and `status` — see the gaps) (`examples/add.axum.rb` text/json, `validate.axum.rb` html, `views.axum.rb` render, `assets.axum.rb` headers; `bin/probe`'s route and filter rows compile `redirect`/`halt`; `test/test_body_surface.rb` pins the default 302, an explicit 303, the status tuples and the content type header, and `test/refusals/redirect_bad_status.rb`/`render_bad_status.rb` pin the refusals; `test/refusals/content_type_in_route.rb` refuses a `content_type` outside a `before`); a `redirect` path is a literal of visible ASCII (0x20-0x7E, or a tab) with no leading or trailing whitespace, or numeric-only interpolation, and a body may not combine `status(...)` with a helper's `status:`, nor `content_type(...)` with a helper's `content_type:` (`test/refusals/redirect_computed_path.rb`, `redirect_interpolated_string.rb`, `redirect_literal_control_byte.rb`, `redirect_literal_edge_space.rb`, `status_and_helper_status.rb`, `status_and_redirect_status.rb`, `content_type_and_statement.rb`), and a helper's `content_type:` is a string literal MIME type with SP/HTAB separators and no CR/LF (`content_type_not_literal.rb`, `content_type_control_byte.rb`). `etag(value)` is the computed conditional-GET header: the response carries `ETag`, and a request whose `If-None-Match` lists the value is answered 304 with no body (`examples/validate.axum.rb` `/etag`, `test/e2e_validate.sh` requests twice, `test/test_compiled_paths.rb` pins the branch) |
| ✓ | views: `render :name, locals: {...}` reads `views/NAME.html` (the folder `set :views` names, default `views`) at compile time and compiles it into the emitted Rust, so the crate carries no template crate and no `.html` file; `set :layout`/`layout: :other`/`layout: nil`, and the ten markers `{{ name }}`, `{{ name\|raw }}`, `{{ name\|sanitize }}`, `{{ yield }}`, `{% raw %}…{% endraw %}`, `{{ partial :name, key: value }}`, `{% for %}`, `{% if %}`, `{{ csrf_token }}` and `{{ asset_path "campfire.css" }}`; a `{{ partial }}` inlines a same-folder `.html` file, whose markers read only the call's arguments, and a cycle is refused. The locals rule is the exact set of the view's and its layout's marker names minus `yield`, refused in both directions with the name. Exercised by `examples/views.axum.rb` and `make e2e-views`: `test/golden/views.main.rs` pins the emitted `format!`, and `test/e2e_views.sh` asserts the form, the two partial fields with different arguments, the re-rendered form with the check()'s message, the escaped marker, the sanitised marker, the `{% raw %}` region byte for byte, the `\|raw` fragment, `layout: nil` and the second layout. Refusals are pinned by `test/refusals/views_*.rb` (and `set_views_symbol.rb`), including a view whose bytes are not valid UTF-8 (`views_invalid_utf8.rb`). See [Views](views.md) |
| ✓ | `{% for x in xs %}…{% endfor %}` in a view, Askama-shaped: the body repeated for each element of a list local (strings, integers, a query's records or a params object list), `{{ x }}` for a scalar element and `{{ x.field }}` for a record field (`\|raw` on both), nesting, `{% for t in x.field %}`, partials taking `x`/`x.field`, loops in layouts and partials; it compiles to a `String`-building block spliced into the page's `format!` with the plain markers' escaper. Refused with the view's file and line: an unclosed `{% for %}`, a stray `{% endfor %}`, a loop variable outside its loop or shadowing a local, a non-list, an unknown field (with the field list), a nil-able field, a record written whole (`examples/notes.axum.rb` `GET /notes.html` with `examples/notes/views/notes.html`; `test/test_compiled_paths.rb` loop tests, `test/refusals/views_loop_*.rb`; `test/e2e_notes.sh` asserts the notes in order and a tag-shaped body escaped). See [Views](views.md) |
| ✓ | `{% if name %}…{% else %}…{% endif %}` in a view, Askama-shaped: one condition, a bool or nil-able local or a bool or nil-able field of an enclosing loop variable; Ruby truthiness (nil and false are false, and `Some(false)` for a nil-able bool), and inside the taken branch a nil-able name reads as its value through a generated `if let` (never an `unwrap`). Both branches' markers count toward the render's `locals:`, and a nested marker, loop, partial or `{% if %}` is just more of the branch. It emits a `String`-building block spliced into the page's `format!` as a loop does. Refused with the view's file and line: `{% elsif %}`, an expression/comparison/negation, an unclosed `{% if %}`, a stray `{% endif %}`, `{% endfor %}` crossing an open `{% if %}`, `{{ yield }}`/`{% args %}` inside a branch, a condition that is not a bool or nil-able (`examples/views.axum.rb` `GET /greeting`; `test/test_compiled_paths.rb` if tests, `test/refusals/views_if_*.rb`; `test/e2e_views.sh` asks for both branches and asserts `data-show` first). See [Views](views.md) |
| ◐ | the marker grammar is fixed at ten forms (`{{ partial }}` takes literals and bare names only, with no named blocks, slots or inheritance beyond `{{ yield }}`; `{% for %}` takes one list name and one new name; otherwise no expressions, no filters beyond `\|raw` and `\|sanitize`, no comparisons and no negation), the delimiters are fixed, and a view's locals are checked only where a `render` names it — a view no render names is never read (`Views::FORMS` in `lib/axum_dsl/views.rb` is the list the refusal quotes; `test/refusals/views_unknown_directive.rb`, `views_unknown_filter.rb` and `views_malformed_marker.rb` pin it; `Views.load` runs only from `Body#render_response`, so a view no render names is never read). It stays this small on purpose: the locals rule is the exact set of marker names, so the grammar must stay closed enough to list them, and the view is compiled into the emitted Rust without a template crate; partial defaults (`{% args %}`), `{% for %}` and `{% if %}` were the widenings, each only as far as one name |
| ✓ | HTML escaping: `h(value)` and `raw(value)` share one implementation (`axum_dsl_html_escape`, emitted into the crate only when a body or a view escapes a value), and a view's `{{ name }}`/`{{ name\|raw }}` are exactly them, so a page and a body escape alike (`Body#html_value` is the one lowering; `Emit::HTML_ESCAPE` is emitted only for `h`/`{{ }}`, pinned by `test/golden/views.main.rs` and `test/golden/validate.main.rs`; `test/e2e_views.sh` and `test/e2e_validate.sh` assert the escaped and the unescaped halves) |
| ◐ | escaping is by value, not by context: `h` and `{{ }}` escape `&`, `<`, `>`, `"` and `'` wherever they are written, so they are right for text and for a quoted attribute value, but a `javascript:` URL in an `href` survives them. `{{ name\|sanitize }}` in a view is the named sanitiser for a value that is already HTML (an Action Text body): ammonia's default allowlist with generic `class`, emitted with its `ammonia` dependency only when a view uses it (`Sanitize::HELPER`, `Emit#cargo`; `examples/views.axum.rb` `GET /sanitize` and `test/e2e_views.sh` assert the kept `<strong>` and the stripped `<script>` and `javascript:` href). `raw`/`{{ name\|raw }}` is the deliberate unescaped door, named for a review to grep; a page whose `{{ }}` belongs to a client framework is a static asset, not a view (`Emit::HTML_ESCAPE` is one five-character replacement with no context; [Views](views.md)' Escaping section states the `javascript:` URL case). It stays by value on purpose: `h`, `{{ }}` and a body's escape are one context-free replacement behind one lowering, which is what keeps a page and a body escaping alike, and anything beyond it has a named door (`\|sanitize`, `raw`, or a static asset) rather than a guess at context |
| ✓ | file serving: `static "/assets", dir: "public"` mounts a directory (tower-http `ServeDir` at a prefix, the fallback at "/" for `set :public_folder`), `serve_file "/x", from: "..."` answers one route with one file (`ServeFile`), and `headers "Cache-Control" => "no-store"` shapes a response beside `status`/`content_type` (`examples/assets.axum.rb` and `test/e2e_assets.sh`, which asserts each content type, the empty 404, the traversal refusal, `serve_file` and the route's own headers, and `digest: true` copies each file under `<stem>-<twelve hex digits of its SHA-256><ext>` and serves only that name, with `{{ asset_path "campfire.css" }}` writing the URL (`test/test_assets.rb` pins the names and refusals, `test/e2e_assets.sh` fetches the fingerprinted file); the mount sends no `Cache-Control` of its own (a `use_layer :private_cache` appends one to every non-exempt response), and `asset_path` sees only a mount declared before the render; the `set :public_folder` fallback is emitted but no example mounts one). A static mount at "/" is the fallback and cannot take `skip:`, which is refused (`test/refusals/static_root_skip.rb`) |
| ✓ | a file response computed at request time: `send_file(path, content_type: "image/webp")` awaits `tokio::fs::read` on each request, answers the bytes with the literal Content-Type, and answers a plain 500 when the read fails. The path is a string expression, so the file is neither declared beside the DSL file nor copied into the crate; a path that came from a request is the application's trust decision, checked before the call (the avatar route answers 404 when its row is absent). `status:` and `status(...)` follow the other helpers' rules. tokio's `fs` feature is added only when a body calls it (`Body#send_file_response`, `AxumDsl::SendFile`; `test/test_send_file.rb`; campfire e2e avatar) |
| ✓ | the declared assets are **copied into the emitted crate** at their own relative path, and `tower-http` is added to Cargo.toml only when a `static`/`serve_file` or a `use_layer` needs it (like `regex`), as one line whose feature list is the union: `fs`, plus `compression-gzip`/`cors`/`timeout`/`trace` for the layers (`Emit#tower_http_dep`; `test/golden/assets.Cargo.toml` pins `fs` alone and `validate.Cargo.toml` the four layer features). The built service must run with the crate directory as its working directory, which `test/e2e_assets.sh` establishes (it starts the binary there and checks the copied bytes) |
| ◐ | serving rules that are not expressed: `ServeDir::redirect_to_trailing_slash` and `redirect_path_prefix` exist only in tower-http 0.7, whose `ServeDir` no longer has `Error = Infallible` (what axum `get_service` and `nest_service` require), so a request for a directory is its `index.html` with no redirect. `headers` takes literal names and values only by design; a computed ETag has its own statement, `etag(value)` (`emit.rb` pins tower-http 0.6 and emits `append_index_html_on_directories(true)` with no redirect; `headers` is a `T::Hash[String, String]` in `SIG`/`Body#headers_stmt`). The redirect stays out until tower-http's `ServeDir` error type fits `get_service`/`nest_service` again; `headers` stays literal by design, a `T::Hash[String, String]` of names and values written in the DSL file |
| ✓ | filters: `before` (axum middleware), `not_found` (axum fallback), `error` (raises, or a plain 500). A `before` may be named (`before :authenticate do ... end`), a route skips one with `skip: [:authenticate]`, and `current ... required: :authenticate` reads the current non-nil in routes that do not skip it; the filter stays a layer, and the emitted skip compares the request's method and URI path with the skipping routes (a capture matches a segment, a `{*tail}` the rest; a skip that could also match a non-skipping route, a `serve_file` or the OpenAPI document is refused). A `static` mount takes the same `skip:` list (GET of the prefix and its subtree; a mount at `/` is axum's fallback, so a `skip:` on it would cover every GET path and is refused, `static_root_skip.rb`, and a mount that needs `skip:` must sit at a prefix; `serve_file`/`set :public_folder` take no skip; `static_skip_unknown.rb`, `filter_skip_serve_file_overlap.rb`, `filter_skip_openapi_overlap.rb`). A duplicate name, an unknown skip on a route or a mount, and a required current on a skipping route are refused (`test/test_compiled_paths.rb`; `test/refusals/filter_duplicate_name.rb`, `filter_skip_unknown.rb`, `filter_skip_overlap.rb`, `current_required_*.rb`; `bin/probe`'s filter row compiles the anonymous form; `examples/validate.axum.rb` declares no `not_found` and `test/e2e_validate.sh` asserts the 404; `test/refusals/content_type_in_not_found.rb`, `content_type_in_route.rb`) |
| ✓ | named middleware: `use_layer :compression`, `:cors` (with `origins:` or permissive), `:timeout` (with `secs:`) and `:trace` put a tower-http 0.6 layer on the router, in a fixed order so where the declaration sits does not matter; a duplicate name is refused (`examples/validate.axum.rb` declares all four and `test/e2e_validate.sh` asserts compression and cors over HTTP; `Emit::LAYER_ORDER`; `test/refusals/layers_*.rb` pin the refusals). `:rate_limit` is the compiler's own std-only fixed-window limiter: `per:`/`burst:` are required, `path:` scopes one exact path, the count is per `request_ip`, and past the burst the answer is 429 (`Emit#rate_limit_runtime`, `Emit::LAYER_ORDER`, no tower-http feature; `examples/login.axum.rb`, `test/e2e_login.sh` bursts the login, `test/test_compiled_paths.rb`; `test/refusals/layers_rate_limit_*.rb`). `:csrf` is the compiler's own token check: it needs `cookies secret:`, sets a signed `_axum_dsl_csrf` cookie when one is absent, reads `{{ csrf_token }}` from the request extension, and answers 403 to a write whose `authenticity_token` field or `X-CSRF-Token` does not match, with `:fetch_metadata` outside it (`lib/axum_dsl/csrf.rb`, `Emit::LAYER_ORDER`; `examples/csrf.axum.rb`, `test/e2e_csrf.sh`, `test/test_csrf.rb`; `test/refusals/csrf_*.rb`) |
| ◐ | `:rate_limit` is a fixed window anchored to the epoch: a client can spend `burst:` at the end of one window and again at the start of the next, so a boundary can allow up to twice the burst; there is no `Retry-After`; the process-wide map never evicts, so distinct client keys grow it without bound; and with `use_layer :trace, forwarded: true` the key is the caller's `X-Forwarded-For` entry, so it is only as trustworthy as the proxy that overwrites it (`Emit#rate_limit_runtime`; `docs/dsl.md`; TODO) |
| ✓ | `helper` with typed args/returns and keyword parameters (`bin/probe`'s `helper with a keyword argument` and `helper with a nil-able parameter` rows compile it; `test/refusals/helper_arity.rb`, `helper_unused.rb`, `duplicate_helper.rb` pin the rules; no example declares one yet) |
| ✓ | `use_dsl`/`fragment` file splicing (`Reader#splice`, `use_dsl` and `fragment` in `SIG`): `examples/split.axum.rb` splices `split/params.axum.rb` and `split/routes.axum.rb`, which itself includes `split/status.axum.rb`; `make e2e-split` (`test/e2e_split.sh`) asserts a route from the root, from a fragment and from a nested fragment, and the params fragment's types (a bad value is a 400); `test/golden/split.main.rs` pins the spliced emit. The fragments sit in a sub-folder, so `examples/*.axum.rb` never builds one |
| ✓ | escape hatches: `rust_crate`, `rust_item`, `rust_fn` (including a `:string?` return), `rust_file`, `file`/`file_text`, `cmd_fn` (argv and `pass: :stdin`), `script_fn` (`sh`, `ruby`) and `use_bindings`. `examples/hatches.axum.rb` reaches each from a route and `make e2e-hatches` (`test/e2e_hatches.sh`) asserts the values, that shell-breaking inputs stay literal, the manifest's `heck` line, and `src/shout.rs` byte-identical to `examples/rust/shout.rs`; `examples/case.axum.rb` and `make e2e-case` cover `use_bindings`. `hatches` has a golden (`test/test_golden.rb`), and `e2e_hatches.sh` runs the binary from the crate directory and asserts the copied `hatches/motd.txt` is byte-identical to `examples/hatches/motd.txt` |
| ◐ | SQL state ([Database](database.md)): `database :sqlite`, `record`, `query`/`execute` with `:name` placeholders, `migrations`; the SQL runs as written, the compiler checks placeholders against `args:` and the server checks every statement and each record's columns once at startup (`Reader#add_query`, `Db::Sql`, `Db::Sqlite`; `examples/notes.axum.rb`, `test/e2e_notes.sh` incl. a restart on the same file and a startup-check refusal, `test/test_db_sql.rb`, `test/refusals/query_*.rb`, `database_unknown_adapter.rb`, `migrations_bad_name.rb`). A bare `query`/`execute` call may stand as a statement, its value dropped, so a DELETE runs for its effect before the route redirects (`test/test_body_surface.rb`). Campfire's message write is the first multi-statement path and is now one `transaction do ... end` (message `RETURNING id`, rich text, FTS row), so a failure between them rolls back; `transaction` is a body form with its own refusals (`test/refusals/transaction_*.rb`, `test/test_compiled_paths.rb`), and a statement called only inside a transaction is emitted as its sync `_on` core with no pooled wrapper, so `-D warnings` stays clean while the crate has no dead wrapper. A statement's argument inside a transaction may only read values already in scope (a literal, a local, `params[...]`, a field read, or a list/hash/interpolation of those), because it is lowered in the `rusqlite::Result` closure after BEGIN: a call there is refused, since a fallible one's error could not cross the closure and non-SQL work would run after BEGIN. Not there: other adapters, nil-able or list arguments |

## The gaps (documented, not hidden)

| | |
|---|---|
| ✓ | `status(...)` is carried through the IR and applied by the emitter to whatever the body ends in; a `before` filter that continues applies it to the response it passes through. The route case is a build: `examples/validate.axum.rb`'s `/signup/soft` sets `status(:accepted)` and `test/e2e_validate.sh` asserts the 202; the `before`-filter pass-through and the integer form are asserted on the emitted Rust by `test/test_compiled_paths.rb`. The integer form emits `StatusCode::from_u16(N).unwrap()`, but `Body#status_code` already refuses a value outside 100..=599 and `from_u16` accepts 100..=999, so the unwrap cannot fire; the symbol form (`status(:accepted)`) is the ergonomic spelling; a body that also uses a helper's `status:` is refused as ambiguous (`test/refusals/status_and_helper_status.rb`) |
| ✓ | a form field must be a scalar: a urlencoded body is flat and serde_urlencoded cannot build a list, a map or a nested object, so the reader refuses such a field `in: :form` and says to send it as a JSON body (`reader.rb` `params_decl`; `test/refusals/form_list_field.rb`, `form_map_field.rb`, `form_object_field.rb`) |
| ✓ | `setting(...)` is declared and read as `setting(:name)` from a route or a filter body; a helper or a binding body cannot read one (`bin/probe`'s `settings: read in a route, a before filter and not_found` row; `SIG`'s `setting` entry; `examples/login.axum.rb` declares one) |
| ✗ | `def` inside a body is refused — inherited, not a regression: `rmcp_dsl` refuses it too and its own skill lists "`while`/`for` loops and `def` inside a body" as refused (`test/refusals/def_in_body.rb`; `bin/probe`'s `def inside a body` row). Sinatra's `helpers do ... def ... end` is not implemented either. It stays refused on purpose: a body is a Ruby subset that compiles to one Rust handler, and reusable code has its own typed home in `helper` (and `rust_fn` for Rust), so a body defining methods is not needed. |
| ✓ | no code path emits an `rmcp::` path: a typed map's `to_json` and `entry_args(...)` emit `serde_json`, and the content-block builders (`image`, `audio`, `resource_link`, `embedded_text`, `embedded_blob`) are **refused** by name — an axum service has no content blocks, so a body answers with `text`, `json` or `html` (`test/refusals/content_block_*.rb` and `resource_content_blob.rb`; `Body` and `emit.rb` spell `serde_json`). |

## Body language

The Ruby subset is `Body::ALLOWED_METHODS` plus response helpers and the escape-hatch calls
(`lib/axum_dsl/body.rb`); `bin/probe` runs about fifty constructs through the compiler one at a time, and
`test/refusals/` pins what the reader refuses. Missing or
broken today: maps are read-only (in-place changes are not supported); deeper collection nesting than a
map of one map is refused (`lib/axum_dsl/composite_types.rb`: a map value is a scalar, a list, a nested
object or one nested map); a string literal on the left of `+` is refused (`"a " + s` must be written
`s + "a"`, and the refusal names that rule — `test/refusals/string_literal_left_of_plus.rb`); `content_type(...)` is only
meaningful in a `before` filter (`test/refusals/content_type_in_route.rb`); a path capture (`in: :path`)
must be a scalar (`test/refusals/path_list_field.rb`).

## Planned order

The ported surface is honest end to end and the deployable wave has landed (PORT/BIND, graceful shutdown,
`forwarded: true`, the deployment section in [the command line](cli.md); `raj/docs/dev/WAVE-PLAN.md` Track
AX, 2026-10-16). What remains is closing the rows above, then growth. In order, with the reason each sits
where it does:

1. **The close-out** (Track AX: the TLS listener hook, logging, the shared-middle examples, the recorded
   paths, OpenAPI from `description:`). It comes first because every row it closes is a claim this table
   already makes.

2. **A dev server** (landed: `axum_dsl dev`, see [the command line](cli.md); `test/e2e_dev.sh`). It watches every
   input the compiler read; re-emits, builds incrementally, restarts. The DSL checker is the fast loop and
   rustc the slow truth (`raj/docs/dev/DSL-PLAN.md`), so this makes the slow half pleasant; it needs no new
   language. Browser live-reload is not part of it.

3. **Partial defaults, Askama-shaped (done: `{% args %}`, `Views.args_decl`).** Before it, every marker a partial writes must be fed by an argument of
   every call. A partial would declare its arguments as a Ruby keyword list, `{% args label:, hint: "" %}`,
   read with Prism as `def _(label:, hint: "")`, and the call `{{ partial :field, label: "Name" }}` (already
   valid Ruby) read with Prism too, so required and defaulted arguments are Ruby's own syntax
   (`Views.partial_args`, `Body#check_partial_locals`). It is a language change; nothing is blocked on it.

4. **State (SQLite landed, see [Database](database.md)), then sessions (landed, see [Sessions](sessions.md)); path-scoped
   `before` filters landed with AX14, so the next steps are regex mappings for Campfire (AX9) and then the Campfire
   milestone, the read-routes-plus-login milestone.** A pool reaching a handler was the first thing the language did not already have, so it was
   designed first: SQL first, deterministic, with an agnostic backend seam and no ORM. Sessions build on it;
   then the milestone `raj/docs/dev/DSL-PLAN.md` names — `bin/check` over the read routes plus
   login/session against the fixture database — is reached long before anything speaks WebSockets. SSE,
   then Action Cable-framed WebSockets, comes after, because a stream is the second concept the body
   language needs and it is cheaper to design once than once per feature.

Also outstanding, and not on that path: the not-expressed gaps above (the directory redirect, a computed header), which wait for a
reason to exist.
